# Специфікація методу

Система: ContactHub CRM (умовна система, використана як навчальний обʼєкт)

## Загальний опис

| Параметр | Значення |
|---|---|
| Назва методу | AddContact |
| HTTP метод | не вказано у вихідній специфікації, визначається в межах завдання |
| Шлях | `http(s)://{URL}/api/v1/contacts` |
| Призначення | Додавання в систему інформації про новий контакт |
| Формат тіла запиту | JSON |

## Вхідні параметри

| Імʼя | Тип | Обовʼязковий | Опис | Значення | Мапінг |
|---|---|---|---|---|---|
| Code | String | Так | Ідентифікатор клієнта у зовнішній системі замовника | | `[Contact].[Code]` |
| Name | String | Ні | ПІБ | | `[Contact].[Name]` |
| MobilePhone | String | Так | Мобільний телефон | | `[Contact].[MobilePhone]` |
| Email | String | Ні | Адреса електронної пошти | | `[Contact].[Email]` |
| BirthDate | Date | Ні | Дата народження контакту | | `[Contact].[BirthDate]` |
| GenderCode | String | Ні | Код значення довідника Стать контакту | 0 жіночий, 1 чоловічий | `[Contact].[Gender]` |

## Приклад тіла запиту

```json
{
  "Code": "",
  "Name": "",
  "MobilePhone": "",
  "Email": "",
  "BirthDate": "",
  "GenderCode": ""
}
```

## Чого немає у специфікації

Коди і структура відповіді, поведінка при дублюванні ідентифікаторів, формат номера телефону, обмеження довжини рядкових полів, спосіб авторизації. Перелік цих прогалин винесено в `04-open-questions.md`.
