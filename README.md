# API Test Cases: Contact creation endpoint

Навчальний кейс з ручного тестування API. Обʼєкт тестування: метод створення контакту у вигаданій CRM-системі ContactHub.

Специфікація методу написана мною на основі типового набору полів адресної книги і не належить жодній компанії.

## Що всередині

| Файл | Зміст |
|---|---|
| `docs/01-api-spec.md` | Специфікація методу, що тестується |
| `docs/02-http-method-analysis.md` | Визначення HTTP методу і обґрунтування вибору |
| `docs/03-test-approach.md` | Підхід до тестування: ізоляція даних, тестові дані, пріоритети |
| `docs/04-open-questions.md` | Питання і прогалини, знайдені в специфікації |
| `test-cases/contact-add-testcases.md` | Набір тест-кейсів у зручному для читання вигляді |
| `test-cases/contact-add-testcases.csv` | Той самий набір для імпорту в TMS або таблицю |
| `postman/` | Колекція Postman з 28 запитів і оточення |

## Обсяг

17 тест-кейсів: 5 позитивних і 12 негативних.

Покриті області: створення з повним і мінімальним набором полів, валідація обовʼязкових полів, унікальність обох ідентифікаторів, мапінг довідника, валідація формату Email, дати народження і номера телефону.

## Ключовий принцип набору

Кожен кейс самодостатній. Він сам створює потрібний стан системи у передумовах і сам прибирає за собою у постумовах. Набір можна прогнати двічі підряд і отримати той самий результат, а окремий кейс можна запустити ізольовано від решти.

## Інструменти

Postman для формування запитів, доступ до бази або до інтерфейсу CRM для перевірки фактичного стану запису.

Колекція лежить у папці `postman`, інструкція із запуску і перелік прийнятих припущень у `postman/README.md`.
