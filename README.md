# Postman

Колекція запитів до методу створення контакту. Повторює тест-кейси з `test-cases/contact-add-testcases.md`.

## Файли

| Файл | Призначення |
|---|---|
| `contact-api.postman_collection.json` | Колекція, 28 запитів |
| `contact-api.postman_environment.json` | Оточення зі змінною baseUrl |

## Структура

```
Contact API - create contact
  01 Positive    10 запитів   TC-001 ... TC-005, кожен кейс плюс його Cleanup
  02 Negative    18 запитів   TC-006 ... TC-017, у кейсів на дублювання є Setup і Cleanup
```

Кожен запит містить у полі Description передумови, очікуваний результат і постумови того самого кейса, що і в основному наборі.

## Як запустити

1. Імпортувати обидва файли в Postman через Import.
2. Обрати оточення ContactHub - test env у випадному списку праворуч вгорі.
3. Підставити реальну адресу в змінну baseUrl.
4. Запускати кейси по порядку всередині папки, або прогнати папку цілком через Runner.

Порядок усередині папки має значення: Setup іде перед основним запитом, Cleanup після нього.

## Автоперевірки

У позитивних кейсах перевіряється код відповіді у діапазоні 2xx, формат JSON і час відповіді. Ідентифікатор створеного запису зберігається у змінну колекції, щоб Cleanup знав, що видаляти.

У негативних кейсах перевіряється код відповіді у діапазоні 4xx, відсутність успішного створення і наявність тіла відповіді з помилкою.

Перевірки навмисно написані на діапазони кодів, а не на конкретні значення. Конкретні коди відповіді у специфікації не описані, і ставити в асерт вигадане число означало б перевіряти власне припущення замість вимоги. Після уточнення від команди розробки діапазони треба замінити на точні коди.

## Обмеження

Метод видалення у специфікації не описаний. Cleanup-запити побудовані на припущенні, що існує `DELETE /api/v1/contacts/{id}`. Це припущення потребує підтвердження. Якщо такого методу немає, постумови виконуються вручну через інтерфейс системи або напряму в базі, а Cleanup-запити з колекції прибираються.

Скрипт збереження ідентифікатора перебирає варіанти назви поля Id, id і data.id, бо структура відповіді теж не описана. Після отримання реальної структури цей перебір треба замінити на одну точну назву поля.

Авторизація в колекції не налаштована з тієї самої причини, спосіб авторизації у специфікації відсутній.
